# Test Cases for Story AAVA-3 – Reset password via email

**Story Summary:** Reset password via email  
**Story Description:** As a user, I want to reset my password via email so that I can regain access to my account if I forget it.  
**Last Updated:** 2026-08-01T13:39:56.577+0530

---

## Acceptance Criteria

1. **AC1:** User can request a reset link by entering their registered email
2. **AC2:** Reset link is valid for 30 minutes only
3. **AC3:** New password must meet complexity rules (min 8 chars, 1 number, 1 special char)
4. **AC4:** User receives a confirmation email after successful reset

---

## Test Cases

### TC-AAVA-3-001 – Request reset link with valid registered email

- **Linked AC:** User can request a reset link by entering their registered email  
- **Type:** Positive  
- **Priority:** High  
- **Preconditions:**  
  - User has an existing active account with a verified email address (e.g., `user@example.com`).  
  - Password reset feature is enabled.

**Steps:**
1. Open the application login page in a supported browser.  
2. Click the **"Forgot password"** link below the login form.  
3. In the **"Email"** field, enter a registered email address (e.g., `user@example.com`).  
4. Click the **"Send reset link"** (or equivalent) button.  
5. Check the inbox of the entered email account (`user@example.com`).

**Expected Result:**  
System displays a confirmation message indicating that a reset link has been sent (without exposing whether the email is registered, per security best practice). A password reset email containing a unique reset link is delivered to the specified email address within acceptable time (e.g., < 2 minutes).

**Assumptions:**
- System uses email-based password reset with a clickable URL.  
- System does not disclose whether the email exists to prevent account enumeration; message is generic (e.g., "If an account exists, we have sent a link").  
- Email delivery infrastructure (SMTP and mail inbox) is functioning and available for testing.

### TC-AAVA-3-006 – Reset link valid and usable within 30-minute window

- **Linked AC:** Reset link is valid for 30 minutes only  
- **Type:** Positive  
- **Priority:** High  
- **Preconditions:**  
  - User has requested a password reset link using a registered email (e.g., `user@example.com`) and received the reset email.

**Steps:**
1. Request a password reset for `user@example.com` and open the reset email.  
2. Within 10 minutes of request (within the 30-minute validity), click the password reset link in the email.  
3. Observe that the password reset page loads successfully.  
4. Enter a valid new password that meets complexity rules and confirm it.  
5. Submit the password reset form.

**Expected Result:**  
Reset link opens a valid password reset page within 30 minutes of generation. Password reset completes successfully, and the user's password is updated.

**Assumptions:**
- Link validity period starts from the timestamp of link generation.  
- No additional constraints (e.g., IP restrictions) are applied that would interfere with basic flow.

- **Type:** Edge

2. Wait until at least 31 minutes have passed since the reset email was generated (verify time via logs or email timestamp).

4. Observe the page or message that appears.

**Expected Result:**  
System displays a clear **"reset link expired"** message and does not allow the user to set a new password using this link. User may be prompted to request a new reset link.

**Assumptions:**
- System time and environment clock are accurate and synchronized.  
- Link expiry is enforced server-side based on token timestamp.

### TC-AAVA-3-009 – Attempt to use tampered or malformed reset token

- **Linked AC:** Reset link is valid for 30 minutes only  
- **Type:** Negative  
- **Priority:** Medium  
- **Preconditions:**  
  - A valid reset link URL structure is known (e.g., contains a token parameter).

**Steps:**
1. Copy a valid password reset URL obtained for `user@example.com`.  
2. Modify the token parameter in the URL by changing or truncating characters to create a malformed or invalid token.  
3. Paste the modified URL into the browser and navigate to it.

**Expected Result:**  
System detects the invalid token and displays an error indicating the link is invalid or cannot be used. No password reset page is displayed that would allow changing any password.

**Assumptions:**
- Reset URLs contain a token parameter that can be manipulated.  
- Server-side validation exists for token integrity and authenticity (e.g., signed tokens).

### TC-AAVA-3-010 – New password meets complexity rules and is accepted

- **Linked AC:** New password must meet complexity rules (min 8 chars, 1 number, 1 special char)  
- **Type:** Positive  
- **Priority:** High  
- **Preconditions:**  
  - User has a valid, non-expired password reset link for `user@example.com` and can access the reset password page.

**Steps:**
1. Open the valid reset password link for `user@example.com` in a supported browser.  
2. On the reset form, enter a new password that is at least 8 characters long and contains at least one numeric digit and one special character (e.g., `"NewPass1!"`).  
3. Enter the same value in the **"Confirm new password"** field.  
4. Submit the password reset form.

**Expected Result:**  
System accepts the new password, displays a success message, and updates the user's password. User can subsequently log in with the new password and cannot log in with the old password.

**Assumptions:**
- Special characters allowed include common symbols such as `!`, `@`, `#`, `$`, `%`, etc.  
- No additional complexity rules apply beyond those specified in the acceptance criteria.

### TC-AAVA-3-018 – Confirmation email sent once per successful reset and not duplicated

- **Linked AC:** User receives a confirmation email after successful reset  
- **Type:** Edge  
- **Priority:** Low  
- **Preconditions:**  
  - User account `user@example.com` exists and has a valid email address.

**Steps:**
1. Request a password reset for `user@example.com` and obtain a valid reset link.  
2. Use the reset link to successfully reset the password with a valid complex password.  
3. Observe the success message for the reset.  
4. Monitor the inbox of `user@example.com` for confirmation emails.  
5. Verify that exactly one confirmation email related to this reset event is received.  
6. Repeat the entire reset process a second time (request new reset link, reset password successfully) and verify a second distinct confirmation email is received.

**Expected Result:**  
For each successful password reset event, the system sends exactly one confirmation email. No duplicate confirmation emails are received for a single reset action.

**Assumptions:**
- System is designed to send one email per successful reset event.  
- Email system is capable of logging or displaying message timestamps to distinguish events.

### TC-AAVA-3-019 – Behavior when confirmation email fails to deliver (mail server issue)

- **Linked AC:** User receives a confirmation email after successful reset  
- **Type:** Edge  
- **Priority:** Low  
- **Preconditions:**  
  - Password reset functionality is operational.  
  - Ability to simulate or observe email delivery failure (e.g., connect to test SMTP that rejects messages).

**Steps:**
1. Configure the test environment so that outgoing emails cannot be delivered (e.g., misconfigured SMTP or blocked network for email).  
2. Request a password reset for `user@example.com` and obtain a valid reset link.  
3. Complete a valid password reset using the reset link, entering a complex password.  
4. Observe the application response after successful reset.  
5. Check mail logs or inbox to confirm that the confirmation email was not delivered due to the simulated failure.

**Expected Result:**  
System completes the password reset successfully, even if the confirmation email cannot be delivered. User is still able to log in with the new password. System logs the email sending failure for audit, but no sensitive error about email infrastructure is exposed to the user.

**Assumptions:**
- Email delivery failures do not roll back password changes.  
- Operations or security logs capture email sending errors for later investigation.
